# byoa

An open-source library that lets an app run its users' own Claude Code or Codex in any sandbox, with their MCP connections and skills. It runs inside the app's own backend. It is never a hosted service.

- Read `SPEC.md` before you change anything. Every change maps to a requirement (R*) and a check (V*).
- Keep `README.md` and `SPEC.md` true. When behavior changes, update both in the same commit.
- Follow the "Lab rules" in `SPEC.md`: only unmodified `claude` and `codex` binaries, the lab's own sign-in page, no client spoofing.
- Bookish (`madeyexz/ai-native-book-reader`) is the first app. Its `site/agent/` and `src/core/connectors.ts` hold the code this library replaces.
- `skills/byoa/` is the agent skill that teaches a coding agent to add byoa to an app (SKILL.md and `reference/api.md`). When the API changes, update it and `docs/` in the same commit; `test/docs.test.ts` (V12) checks the names in the README, `docs/` and the skill.
- The docs are the Markdown files in `docs/` (`docs/README.md` is the docs home, and its list of pages is the site's menu). Keep them true with README and SPEC: when behavior changes, update the docs page that describes it in the same commit. README.md has only the pitch, the install, a short example and links into the docs. A docs page puts in another file's text with `<!-- include: ../FILE.md#section -->` (the API reference page is `skills/byoa/reference/api.md`; the lab rules come from SPEC.md and the skill), so each fact has one source. The lifecycle diagrams are ```` ```flow ```` blocks of YAML in `docs/ai-login.md`, `docs/sandbox-lifecycle.md` and `docs/concepts.md`; CONTRIBUTING.md ("Flow diagrams") shows the format.
- The site at https://byoa.rippling.computer is built by `site/build.mjs`. The home page's design (hero, "What works") is in `site/template.html`, the "Who brings what" diagram in `site/diagrams/who.html` (also on the Concepts page), the styles both pages share in `site/base.css`, and the install commands are the code block of "Install" in `README.md`. The home page has only the hero, that diagram, "Get started", "What works" and a short close. The docs pages use `site/docs.html` and `site/docs.js` (flow diagrams, search, menu). `node build.mjs` puts `site/help.html`, the help agent's chat (its backend is `madeyexz/byoa-help` on Convex), before `</body>` of the home page, each docs page and `/demo`: a robot that jumps in and says what it is in a speech bubble, and opens the chat. Keep facts in the template true to `SPEC.md`. The pixel art is in `site/art/` and the fonts (Geist, OFL) in `site/fonts/`. `node build.mjs` writes `site/index.html`, `site/docs/` (each page as `.html` and `.md`, and `search.json`), `site/llms.txt`, `site/llms-full.txt` (https://llmstxt.org) and `site/sitemap.xml`, from `docs/`, README.md, SPEC.md, `examples/todo` and `skills/byoa`, and `site/demo.html`, the live demo at `/demo`, from `examples/mail/demo.html` (its backend is the Convex deployment in `examples/mail/convex`; deploy it with `npm run deploy` there). After a change to any of them or to `site/`, run `cd site && npm install && node build.mjs`, and push what it writes with any changed art or fonts. `node preview.mjs` runs the Worker on the local files. The README's images in `.github/readme/` (banner, "Who brings what", "What works", the closing band, the social preview) are captured from the built page by `site/readme-art.sh`; after a template change that they show, run it after `node build.mjs`. The Cloudflare Worker `byoa-site` (`site/worker.js`, custom domain `byoa.rippling.computer`) serves the files that build.mjs writes, `site/art/` and `site/fonts/` from `main`, so it needs no redeploy unless `site/worker.js` changes (its routes: `/`, `/demo`, `/docs`, `/docs/<page>`, `/docs/<page>.md`). The site counts visits in the PostHog project "rippling.computer" (public key only, never a personal API key): `node build.mjs` puts `site/posthog.html` before `</head>` on every HTML page, for a `$pageview` on each visit (not on localhost); with the same visitor id, `site/help.html` sends `help_opened` when a visitor opens the chat and `help_asked` for each question, and `/demo` sends `demo_signin_clicked` and `demo_job_finished`; the Worker sends a `markdown_view` for each read of `/docs/<page>.md`, `llms.txt` and `llms-full.txt`, which agents read without running a script. `site/worker.js` itself holds `/robots.txt` (every crawler and AI agent may read every page) and the IndexNow key file. The zone has a configuration rule that turns Browser Integrity Check off for `byoa.rippling.computer`, because it answered 403 to agent tools that fetch with Python's urllib.
