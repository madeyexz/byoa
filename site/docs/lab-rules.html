Lab rules

byoa runs the labs' own CLIs on each user's own plan, so byoa and every app on it follow the labs' published rules. This page has the rules from SPEC.md, and what each app must do.

#Rules we follow

  • We run the real, unmodified claude and codex binaries. We never pretend to be another client. A test checks the hash of the installed binaries against the published packages (V11).
  • The user signs in through Anthropic's or OpenAI's own sign-in page.
  • One app's AI login is used only by that app.
  • The labs' terms restrict where an AI login may be stored. byoa keeps it in your database by default, so each app checks those terms and signs its own agreements with the labs.

#What the labs' terms say

byoa follows the labs' published rules as read on 2026-11-22:

  • Anthropic (legal and compliance) allows an end user to sign in to the unmodified Claude Code binary with their own plan, including where a platform hosts Claude Code. It forbids third parties to "collect, store, or intermediate Claude.ai credentials or session tokens", unless Anthropic agrees otherwise.
  • OpenAI (Sign in with ChatGPT Terms, effective 2026-11-04) requires that "any persistent storage of Authentication Tokens must be local and under the user's control, not in a remote or managed environment", and that the plan is used "only for the application they connected". Paid or remotely hosted apps must apply to be partners.

So byoa MUST:

  • run only unmodified claude and codex binaries, and never pretend to be another client;
  • send the user to the lab's own sign-in page;
  • not share one AI login between apps.

The labs' terms above restrict where these tokens may be stored. byoa keeps the AI login in the app's database by default (R1.4), and ships a per-user volume as an option (R1.5). Each app checks the labs' terms for its own use.

Each app is responsible for its own agreements with the labs. We plan to sign agreements for our own apps when they have traction.

#What your app must do

Every app on byoa must follow these rules. If a request breaks one, stop and tell the developer.

  • Run only the unmodified claude and codex binaries that byoa installs (pinned, and checked in byoa's own tests). Do not patch them, wrap them to change what they send, or set headers or a user agent to pretend to be another client.
  • Send the user to the lab's own sign-in page, from connectLogin. Do not embed, proxy or copy that page, and never ask the user for a password or an API key in place of it.
  • Never read, export or call the labs' APIs with the user's AI tokens. The CLI is the only client that uses them. Do not call the labs' token endpoints.
  • One app's AI login is only for that app. Give each app its own app name and its own store. Never share a login between apps.
  • Real MCP tokens never go into the sandbox. Give a job its servers with mcp: [...]. Never put a grant's token in setup, the task, environment variables or files.
  • The labs' terms restrict where AI logins may be stored. Anthropic says third parties may not "collect, store, or intermediate Claude.ai credentials or session tokens" without its agreement. OpenAI says stored tokens must be "local and under the user's control", and paid or hosted apps must apply to be partners. byoa's default keeps the login in the app's database; cliLogin keeps it in a per-user volume. Each app checks the terms and makes its own agreements: https://github.com/madeyexz/byoa/blob/main/SPEC.md#lab-rules
